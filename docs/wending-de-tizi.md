# 稳定的梯子靠什么：分清服务、线路与客户端策略

> “稳定的梯子”要分层阅读，服务与线路由提供方处理，本机配置和客户端策略则涉及使用者。自动选择或故障转移只是客户端的行为，不能代替对其他环节的了解。

> 依据:mihomo 配置文档与 Clash Verge Rev 文档 · 最近核对 2026-10-29

## 稳定性需要分开看哪些层？

通用说明：先分服务、线路、本机设置与客户端策略，再对应能改动的内容。

| 层次 | 谁管理 | 观察什么表现 | 使用者能核对什么 |
| --- | --- | --- | --- |
| 服务 | 服务提供方 | 服务是否仍可使用 | 提供方的服务说明 |
| 线路 | 服务提供方 | 连接状况是否发生变化 | 不把客户端策略当作线路本身 |
| 本机设置 | 使用者 | 当前出口是否符合预期 | 运行模式和配置规则 |
| 客户端策略 | 使用者 | 手动选择还是按条件切换 | 策略组的类型与行为 |

这张表是层次整理，不是故障诊断结果。关于工具与使用方式的区别，可读[代理工具与客户端的概念说明](https://www.jiediancha.com/tizi/)。

## 策略组怎样决定切换？

mihomo 文档给出的手动、测试与超时切换行为不同。

策略组用于组织连接的选择方式。proxies 是组内列出的条目，选择规则由组类型决定。

| 类型 | 文档记载的行为 |
| --- | --- |
| select | 由使用者手动切换组内条目 |
| url-test | 根据测试地址与测试间隔进行延迟测试，自动选择 |
| fallback | 当前连接超时后，沿组内顺序找最先可用的条目 |

url-test 的 tolerance 表示切换容差，单位是毫秒。它和测试间隔不是同一项信息，不能只凭类型名补出具体切换条件。

## 占位配置表示什么？

下面只展示手动选择组，名称是占位内容。

```yaml
proxy-groups:
  - name: "手动选择"
    type: select
    proxies: [节点A, 节点B]
```

这个片段只对应 select 的结构，没有提供真实连接。其他组的自动选择行为，要按各自的类型说明阅读，而不是仅改一个组名。

## 检查参数与出口怎样区分？

健康检查决定如何探测，运行模式决定流量按什么方式出去。

| 名称 | 文档描述 |
| --- | --- |
| url | 检查所用的目标 |
| interval | 检查间隔，单位为秒 |
| timeout | 超时设置，单位为毫秒 |

Clash Verge Rev 文档把规则模式描述为按配置规则选出口，全局模式使用手动选定的代理或本地出口，直连模式则从本地网络出去。它们与组里的手动选择、自动测试、故障转移需要分开读。

## 观察变化时记录哪些内容？

记录当前模式、策略组类型和对应条件，不把所有变化都叫作掉线。

- 看当前运行模式在决定什么出口。
- 看策略组是否由使用者手动选择。
- 看自动选择依赖测试，还是依赖当前连接超时。

哪种类型更稳定，文档没有说明。对组行为的了解也不是对服务和线路的保证，相关概念可接着读[连接与配置的常见问题](https://www.jiediancha.com/faq/)。

## 常见问题

### select 就会自动故障转移吗？

文档将它描述为手动选择，不能把 fallback 的超时切换行为直接套给它。

### fallback 会随意换条目吗？

它在当前连接超时后按组内顺序选择可用条目，顺序是行为的一部分。

### 改策略组就能保证稳定吗？

不能由组的选择行为保证全部环节，服务、线路与本机配置仍属于不同层次。
