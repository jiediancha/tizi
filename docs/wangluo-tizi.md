# 网络梯子连上后哪些程序走：系统代理和 TUN 的区别

> 只开系统代理，不代表每个程序都会采用代理连接。接管方式决定哪些连接进入代理客户端，规则模式决定进入后怎样处理。

> 依据:Clash Verge Rev 文档名词解释页与 Clash Party 项目说明 · 最近核对 2026-11-05

## 系统代理管到哪里？

系统代理需要程序遵守对应设置，不是对所有程序统一接管。Clash Verge Rev 文档还写明，它不能代理 UDP。

UDP 是一种传输协议。程序没有采用系统代理设置，与连接使用什么协议，是查看连接去向时要分开核对的事。

| 对照内容 | 系统代理 | TUN |
| --- | --- | --- |
| 接管方式 | 程序遵守系统代理设置 | 使用虚拟网卡接管 |
| 是否只看程序开没打开 | 还要看程序是否采用设置 | 要看是否由虚拟网卡接管 |
| 与后续规则的关系 | 接管后再按模式处理 | 接管后同样需要看模式 |

连接成功的提示不能代替逐个程序的接管情况。某个程序可用，也不能直接推断其他程序采用了同样的连接方式。

## TUN 与全局模式相同吗？

TUN 是接管方式，全局是对已接管连接的处理模式。两者回答不同问题，不能只因切到全局，就认定所有程序都进入了客户端。

TUN 使用虚拟网卡接管连接。虚拟网卡是软件提供的网络接口，与程序主动读取系统代理设置是不同接入方式。

- 系统代理或 TUN：看哪些连接被接入。
- 规则、全局或直连：看接入以后怎样走。

规则模式仍需要先有被接管的连接。排查时先看接管，再看处理方式，避免只围绕模式名称反复切换。

## 什么时候考虑 TUN？

游戏、部分命令行工具或不读系统代理设置的软件，可能在只开系统代理时不经过代理客户端。这是可能情形，不是对每个程序的确定判断。

可以先区分当前程序是否采用系统代理，再看是否需要虚拟网卡接管。不能只凭别的程序能用，就把当前程序的现象认定为节点失效。

| 观察到的情况 | 先分辨的问题 |
| --- | --- |
| 部分程序采用代理，部分没有 | 是否遵守系统代理设置 |
| 切换全局后仍有程序不走 | 是否已经被接管 |
| 涉及 UDP 的连接 | 是否误把系统代理当作 UDP 接管方式 |

## 权限要求去哪里看？

TUN 的权限与运行条件看具体客户端说明。Clash Party 项目列出不需要服务模式的 TUN，不能把这一项说明套到其他客户端。

不需要服务模式也不能直接换成所有权限条件都相同。查看时保留项目说明的范围，再对照正在使用的程序。

继续了解接管与连接，可看[代理工具与连接方式说明](https://www.jiediancha.com/vpn/)。遇到其他现象时，另看[客户端连接常见问题](https://www.jiediancha.com/faq/)。

## 常见问题

**问：改成全局就接管全部程序吗？** 不是同一件事，全局处理的是已经接管的连接。

**问：系统代理能处理 UDP 吗？** Clash Verge Rev 的名词文档写明系统代理不能代理 UDP。

**问：Clash Party 的 TUN 要服务模式吗？** 项目说明写明不需要，其他客户端看各自说明。
